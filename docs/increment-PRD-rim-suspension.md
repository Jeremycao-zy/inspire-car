# 增量 PRD：混元 3D 轮毂生成 + 车身悬挂高低调节

> 文档类型：增量开发 PRD（仅描述本次变更）
> 项目：灵感改装 / INSPIRE CAR（根目录 `garage-vite`）
> 作者：产品经理 许清楚（Xu）
> 语言：简体中文
> 红线：① 凭证失效绝不降级返回 DEMO 预置模型；② 轮毂生成失败必须优雅提示、不崩。

---

## ① 产品目标（一句话）

让用户在 INSPIRE CAR 中**用一张轮毂照片生成高精度 3D 轮毂并一键换装到真车轮位**，同时**通过真实物理联动的悬挂高低滑杆直观调校车身姿态**，二者均符合真实改装规则。

---

## ② 用户故事

### 需求 1：混元 3D 轮毂生成 + 替换 + 装车（精度拉满）

- **US-1.1（普通车主）**：作为想改装轮毂的车主，我上传一张自己轮毂/轮辋的照片，系统生成高精度 3D 轮毂模型，自动替换原车 4 个轮子并装车，这样我能在 3D 里提前看到实车效果，不用先花钱买。
- **US-1.2（细节党）**：作为在意还原度的玩家，我选择「精度拉满（极限档）」，让生成的轮毂辐条、中心盖、螺栓孔等细节尽量清楚，这样改出来的车和真实轮毂更一致。
- **US-1.3（失败兜底）**：作为遇到网络/凭证异常的用户，我生成失败时看到明确的错误提示和恢复按钮，而不是看到一辆莫名其妙的 DEMO 预置车或页面崩溃。

### 需求 2：车身悬挂高低调节（真实物理联动）

- **US-2.1（姿态玩家）**：作为喜欢低趴姿态的用户，我拖动「悬挂高低」滑杆降低车身，实时看到离地间隙、轮拱间隙、降低量读数同步变化，且轮眉与轮胎的 gap 真实收窄，这样我能把握降低幅度而不蹭胎。
- **US-2.2（合规党）**：作为在意法规的用户，我在读数接近红线（如离地 <100mm、降低 >50mm、轮拱 <10mm）时收到预警，这样我不会调到违法或危险姿态。
- **US-2.3（换胎联动）**：作为同时改轮毂轮胎的用户，我改变轮胎尺寸（直径/扁平比）后，悬挂读数与轮拱间隙会随之重新计算，这样大小轮配低趴时数据依然真实可信。

## ③ 需求池（P0 / P1 / P2）

每条含 **需求 / 验收标准 / 真实改装规则约束**。

### P0（Must have，本次必交付）

**P0-1 轮毂照片→高精度 3D 生成→替换原车 4 轮→装车**
- 需求：前端「上传轮毂照片」入口接入混元 3D LIVE（provider=`hy-3d`，TC3 签名，零账号 `tcproxy` token）；生成 GLB 后自动替换底盘 4 个轮位（clone 装配，非车壳贴图）。
- 验收标准：
  - 上传单张轮毂照片（jpg/png，主视角清晰）后，SSE 进度条 → 成功返回 GLB → 4 个轮子同步换成新轮毂。
  - 生成参数读取 PRD ④ 档位建议值；**默认走「高精」档**（extreme 为探顶占位档，探顶矩阵通过前不启用），用户可切标准/极限。
  - 轮毂 prompt 默认 `'alloy car wheel rim, rim only, no tire'`；导出 GLB（ResultFormat `GLB`，EnablePBR `true`）。
- 真实改装规则约束：不适用（几何生成），但须保证「仅轮辋、不含轮胎」，与底盘真实轮胎几何体解耦，避免双重轮胎。

**P0-2 生成失败优雅降级（不崩、不返 DEMO）**
- 需求：凭证失效 / 超时 / 引擎错误三类失败分别给出明确提示与恢复入口；绝不返回 DEMO 预置模型。
- 验收标准：
  - `auth_error` → 提示「凭证需刷新」并给换票引导按钮。
  - `timeout` / `fail` / `no-engine-key` → 提示具体原因 + 「重试」按钮，**UI 不崩溃、3D 场景保持可用**。
  - 验证：手动让 token 失效，确认页面不出现 DEMO 车、不白屏。
- 真实改装规则约束：红线——凭证失效绝不降级 DEMO（server 已保证，前端须延续）。

**P0-3 悬挂高低滑杆 + 实时读数（真实物理联动）**
- 需求：新增「悬挂高低（mm）」滑杆，降低量 Δ 驱动车身（车壳、轮拱、侧裙、底盘承载件）相对车轮下移 Δ，并实时显示离地间隙 / 轮拱间隙 / 降低量。
- 验收标准：
  - 默认 Δ=0；滑杆范围建议 [−10（升）, +75（降）] mm，单位 mm，步进 1mm。
  - 拖动时：离地间隙 = 基准离地 − Δ；轮拱间隙 = 基准轮拱 − Δ；三读数实时刷新（≤1 帧延迟）。
  - 车轮接地位置与轮胎几何（外径）在仅调悬挂时**不变**；车身姿态真实下移。
- 真实改装规则约束（联动红线，见 ⑤）：
  - 离地间隙 ≥ 100mm（澳洲 ADR 最低）；
  - 总高变化 |Δ| ≤ 50mm 为合规区，>50mm 标红预警；
  - 轮拱间隙 ≥ 10mm 安全、≥5mm 为绝对下限，<5mm 标「蹭胎/触底风险」、<0 标「必蹭胎」。

## ④ 轮毂生成参数「拉满」取值建议

> ⚠️ **风险声明（必读）**：混元 3D 的 `FaceCount` 真实上限**当前未知**（见 `memory/2026-08-29.md` Q6）。历史已把车 180k→220k、轮 120k→150k 调高，但未敢更大以免生成 FAIL。**「拉满」取值必须由工程师 + QA 在上线前实测探顶，确认不触发 FAIL 后再固化，禁止凭推测直接写死最高值。**

### 当前可调参数面（基于 server 代码调研）
- 入口：`server/index.mjs` `handleGenerate` → `server/hunyuan3d.mjs.submitJob`
- 可覆盖项：`faceCount`、`model`（默认 `'3.1'`）、`enablePbr`（已 `true`）、输入分辨率（`src/api/generate.js` `shrinkImage`）、`prompt`（轮毂专用）
- 常量：`DEFAULT_FACE_COUNT = { car: 220000, wheel: 150000 }`（`server/index.mjs:32`）
- 红线出口：`auth_error`→换票引导；`no-engine-key`→`fail()`；catch→`fail()`；**均不降级 DEMO**

### 「极限档」建议取值（待实测确认）
| 参数 | 当前值 | 极限档建议 | 说明 |
|---|---|---|---|
| `faceCount`（轮毂） | 150000 | **220000 – 300000**（建议起点 250000） | 用户「数值开到最大」；**上限须实测探顶** |
| `model` | `3.1` | `3.1`（确认有无更高保真型号再升） | 默认已较新 |
| `EnablePBR` | `true` | `true`（保持） | 已有，导出带 PBR 约 30–45MB |
| 输入分辨率 `maxSide` | 2048 | **2048 → 尝试 4096**（须确认引擎输入限制） | 高分辨率利于辐条细节；需测是否超时/拒收 |
| 输入质量 `quality` | 0.9 | 0.92 – 0.95 | 轻微提升，注意体积 |
| 轮毂 `prompt` | `'alloy car wheel rim, rim only, no tire'` | 保持 + 可补 `'symmetrical spokes, center cap, lug bolts'` | 强调仅轮辋、细节要素 |

**固化前必做**：工程师用真实轮毂图跑 faceCount={200k,250k,300k,350k} × 分辨率{2048,4096} 矩阵，记录成功率/耗时/FAIL 率，取「成功率 100% 且耗时可接受」的最高组合作为极限档默认值；QA 复核导出 GLB 在 THREE 中可正常加载、无破面。

## ⑤ 悬挂调节真实物理规则（可量化联动公式）

> 目标：直接可落地为代码，严格符合真实改装物理。假定**仅调悬挂时车轮/轮胎几何不变**，车身（车壳+轮拱+侧裙+底盘承载件）相对车轮下移 Δ。

### 基础量（来自现有代码）
- 轮胎外径（mm）：
  `odMm = 轮辋直径(mm) + 2 × 胎宽(mm) × (扁平比 / 100)`
  （即 `tire.js: tireOuterRadius = (rimInch×25.4)/2000 + (tireWidthMm/1000)×(aspect/100)`，单位 m；×1000 得 mm）
- 基准离地间隙（mm）：`baseGC = RATIO.rideHeight × L × 1000`（`chassis.js`，`RATIO.rideHeight = 0.0272`，L=车长 m）
- 基准轮拱间隙（mm）：`baseFG = ARCH_CLEARANCE × 1000`（相对轮胎外半径偏置，`ARCH_CLEARANCE = 0.045` m）；实际间隙 = `基准轮拱几何 − 轮胎外半径`偏移换算，最终随车身降 Δ 而减 Δ

### 核心联动公式（降低量 Δ，单位 mm，Δ>0 表示降低）
```
rideHeight_new(m)   = (baseGC − Δ) / 1000          // 车身整体下移 Δ
groundClearance(mm) = baseGC − Δ                    // 离地间隙线性减小
fenderGap(mm)       = baseFG − Δ                    // 轮拱(轮眉)与轮胎顶 gap 线性减小
wheelExposureRatio  = f(Δ) 单调递增                  // 车身越低，轮胎露出比例越大（可视化为轮眉遮罩下移）
```
- 车轮接地位置、轮胎外径 `odMm`、轮心高度在仅调悬挂时**不变**；Δ 只移动「车身相对车轮」的位置。
- 与轮胎尺寸联动：当 `rimInch / tireWidthMm / aspect` 变化时，`odMm` 重算 → `baseGC / baseFG` 重算 → 悬挂读数随之刷新（满足 US-2.3）。

### 真实改装红线（阈值，驱动 UI 着色与预警）
| 指标 | 安全 | 临界(黄) | 危险(红) | 依据 |
|---|---|---|---|---|
| 离地间隙 | ≥120mm | 100–120mm | <100mm | 澳洲 ADR 最低 100mm |
| 总高变化 \|Δ\| | ≤30mm | 30–50mm | >50mm | 多数套装最佳降 30–50mm；ADR/TEIN 总高变 ≤50mm |
| 轮拱间隙 | ≥10mm | 5–10mm | <5mm（<0 必蹭） | 胎—翼子板最小 5–10mm(一指)，安全 10–20mm |

- 降低导致**负倾角**趋势：Δ 较大时建议在 UI 提示「需做四轮定位」，属真实物理后果，非强制计算。
- 动态压缩：静态读数仅作参考，提示「过坎/满载时间隙会进一步减小」即可，不强制建模悬挂行程。

## ⑦ 待确认问题（≤5 条）

1. **faceCount 真实上限？** 记忆 Q6 未解——极限档轮毂建议 250k 起，但是否能到 300k/350k 需工程师+QA 实测探顶，避免生成 FAIL（PRD ④ 已列矩阵测试法）。

5. **轮拱间隙负值（蹭胎）判定与处置**：<5mm 仅 warn 还是直接禁用「应用到场景」？<0 是否强制拦截？需定交互强度。
